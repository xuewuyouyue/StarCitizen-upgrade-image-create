# 图库与数据维护

命令均在项目根目录执行。若使用自定义 `DATA_DIR`，备份、初始化和重建缩略图时必须加载同一份环境配置，避免操作错误目录。

## 日常维护

管理员可在网页维护中英文名称、美元价格和图片，普通用户可选船、生成图片、保存自己的配置和留言。删除舰船为数据库软删除，旧文件不会立即清理。重复载入页面样例不会向共用图库新增样例舰船。

随附清单用于首次安装。重新执行 `npm run seed-catalog` 不应作为覆盖管理员已有修改的更新方式；更新价格和图片请通过管理界面进行。管理员上传的图片上限为 6 MiB，格式为 JPG、PNG 或 WebP。

```sh
npm run thumbnails
```

该命令为运行图库生成缺失的缩略图。也可显式指定包含 `images/` 的数据目录：

```sh
node scripts/generate-thumbnails.mjs /var/lib/wb-image-generator
```

## 备份

先确认站点已至少成功启动一次，并确认备份目标是尚不存在、且位于数据目录之外的新目录：

```sh
node scripts/backup.mjs /absolute/path/to/new-backup-directory
```

脚本使用 SQLite 备份接口生成一致的数据库快照，并复制原图与历史快照，输出目录包含：

- `studio.sqlite`：舰船、账号、配置、权限及留言数据。
- `images/`：原图。
- `history/`：运行目录 `backups/` 的副本。

缩略图可由原图重建，因此备份脚本不复制 `thumbnails/`。数据库和图片不是跨文件事务；为了保留两者完全一致的时间点，执行完整备份期间暂停图库写入，或停服备份。将备份放到受保护的独立存储，避免把用户数据上传到公开仓库。

## 恢复

1. 停止应用服务，保留当前整个数据目录作为回退副本。确认使用的备份目录和目标 `DATA_DIR`。
2. 在新的目标数据目录中恢复 `studio.sqlite`、`images/`；将备份的 `history/` 恢复为 `backups/`。不要把数据库文件直接覆盖到仍在运行的进程，也不要将旧的 `-wal` / `-shm` 文件混入恢复目录。
3. 设置服务账号对恢复目录的读写权限，重建缩略图，然后启动应用。
4. 检查 `/health`、舰船数量、原图和缩略图、登录与个人配置、管理员权限以及留言。确认无误后再移除回退副本。

## 更新与回退

更新前保留原源码、`package-lock.json` 与完整数据备份；新版本执行 `npm ci`、`npm test`。数据库结构可能在启动时迁移，不能只回退源码而假定旧版本仍能读取新数据库。若需整体回退，应停止服务并恢复与旧源码相配的数据备份。应用重启会清除内存会话，用户需重新登录。
